## PHASE 3: MEDIUM - First Sprint After Release

- [x] TASK-003: Cap decompressed archive size and stop blocking the main thread
  - Domain: Security / Core Workflows
  - Severity: MEDIUM
  - Effort: M
  - Depends on: none
  - Files: `src/lib/archive/tar.ts` (58-94), `src/lib/archive/zip.ts` (79-90), `src/lib/archive/detect.ts`
  - What to do: `MAX_ARCHIVE_BYTES` caps the *compressed* file only. `readTar` reads the whole
    file and calls `gunzipSync` on it; `readZip` calls `inflateSync` per entry with
    attacker-controlled `size`. A 200 MB gzip or a small zip bomb can expand to gigabytes and
    freeze or crash the tab. Add a `MAX_UNPACKED_BYTES` budget (e.g. 512 MB total, 64 MB per
    entry) checked before inflating, use `fflate`'s async/incremental APIs or a Worker, and
    report "archive expands beyond the safe limit" instead of running out of memory.
  - Done when: a gzip/zip bomb fixture is rejected with a friendly message and the main
    thread stays responsive; new tests cover total and per-entry limits.

- [x] TASK-004: Fix light-theme contrast for semantic text colours

- [x] TASK-011: Add a webhook freshness window and verify licence callbacks
  - Domain: Security
  - Severity: MEDIUM
  - Effort: S

  - What to do: The signature covers `ts + body` but the handler never checks that `ts` is

    crafted `/api/appsumo/oauth?code=...` link cannot bind a licence to someone else's browser.

  - Domain: Core Workflows
  - Severity: MEDIUM
  - Effort: M
  - Depends on: none

  - What to do: `detect()` runs every unpacker's `score()` and the winning `unpack()` inside a

    above a soft input cap (e.g. 1 MB) with an explicit message, and show a "decoding…" state.
  - Done when: pasting a 5 MB blob does not block typing and the UI states why it stopped.
